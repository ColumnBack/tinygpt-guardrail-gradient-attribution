# Occlusion 분석

단어를 하나 지우고 점수가 얼마나 떨어지는지 **직접** 잰다. 코드는 `occlusion_analysis.py`다.
기울기 없이 forward만 쓰기 때문에 바꾼 만큼은 정확하고, 내부를 볼 수 없는 모델(상용 API 등)에도 쓸 수 있다.

## 식

점수는 IG와 같은 $S(X) = Z[\text{<call>}, y]$ 다.

$$
\mathrm{occ}_i = S(X) - S(X \text{에서 토큰 } i \text{ 제거}) \qquad (> 0:\ \text{그 토큰이 } y \text{를 밀어 줌})
$$

"제거"하는 방법 세 가지:

| 방법 | 하는 일 | 주의 |
|---|---|---|
| zero | 그 토큰 임베딩을 0으로 | IG의 기준점 X'와 같음 |
| mean | 전체 어휘 임베딩의 평균으로 | "평범한 토큰"으로 바꾸는 셈 |
| delete | 토큰을 빼서 문장을 줄임 | 뒤 토큰들의 위치가 한 칸씩 당겨짐 |

**상호작용** — 두 토큰을 함께 지웠을 때:

$$
I_{ij} = \mathrm{occ}_{ij} - \mathrm{occ}_i - \mathrm{occ}_j
$$

$I_{ij} \ne 0$ 이면 두 토큰이 독립적으로 작동하지 않는다. 토큰 하나씩 매기는 점수는 이것을 놓친다.

## 결과: `draft` 사례 (B, S = Z[<call>, write_file])

| 토큰 | zero | mean | delete | IG |
|---|---|---|---|---|
| **draft** | **21.10** | **21.01** | **20.39** | **22.15** |
| log | 2.22 | 2.24 | 2.54 | 1.21 |
| read | 1.15 | 1.26 | 0.05 | −3.29 |
| file | 0.00 | 0.01 | 0.00 | 4.92 |
| 첫 the | 0.03 | 0.07 | **4.42** | 0.17 |

- 세 방법 모두 `draft`가 압도적이고, `draft`를 지우면 정답 `read_file`로 돌아온다.
- **작은 기여는 IG와 다르게 본다.** `file`은 IG 4.92인데 occlusion은 0이다. occlusion은 "하나만 지운 효과"이고,
  IG는 "모두 0에서 함께 키워 가는 경로 위의 기여"라서 측정하는 것이 다르다. 이 문장에서 요청 단어들의 순위 상관(Spearman)은 0.13~0.32이고, 오판 전체 평균은 0.35다.
- **delete의 함정**: 첫 `the`를 빼면 4.42가 나온다. 단어 자체가 아니라 뒤 단어들의 위치가 바뀐 효과다.
- **상호작용**: `read`와 `log`를 함께 지우면 $I = -3.72$ 다. 둘을 합친 효과가 따로 지운 효과의 합보다 작다.
  두 단어가 같은 정보("파일을 읽는다")를 겹쳐서 주고 있다는 뜻이다.

## 결과: 모든 오판 사례 (`--summary`)

| | zero | mean | delete | IG |
|---|---|---|---|---|
| 바뀐 단어가 1위 (처음 모델, 207건) | 88% | 88% | 83% | 88% |
| 지우면 정답으로 돌아옴 | 100% | 100% | 100% | – |
| 바뀐 단어가 1위 (보강 후, 69건) | 93% | 91% | 80% | 68% |

- 가장 큰 원인 단어는 occlusion과 IG가 대체로 같이 찾는다.
- 보강한 모델에서는 IG가 1위로 꼽는 비율이 떨어진다. 남은 오판이 단어 하나보다 여러 토큰의 조합에 걸쳐 있다는 신호일 수 있다(확인 필요).

## 실행

```bash
python occlusion_analysis.py                    # draft 문장
python occlusion_analysis.py --text "문장"
python occlusion_analysis.py --summary          # 모든 오판 사례
python occlusion_analysis.py --augment --summary
```
